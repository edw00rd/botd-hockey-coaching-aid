BOTD HOCKEY COACHING AID — VERSION 4.4
Creator: Nicholas Heller
Release date: 2026-08-03

OVERVIEW

BOTD Hockey Coaching Aid is a standalone, browser-based HTML5 coaching board for
building, drawing, animating, saving, and presenting hockey plays. It is designed
for desktop browsers with a mouse and for iPad use with touch or Apple Pencil.
The complete application is contained in index.html. It requires no account,
installation, external JavaScript library, server-side application, database, or
runtime asset folder.

Nicholas Heller is acknowledged in the HTML source and this README as the creator
of the application, its product concept, coaching workflow, feature direction,
and user experience.

GITHUB PACKAGE CONTENTS

BOTD_Hockey_Coaching_Aid_v4.4_GitHub.zip contains exactly these four current files
at its root. There is no enclosing folder.

- index.html
  The complete Version 4.4 application and GitHub Pages entry point.
- README.txt
  Deployment instructions, Version 4.4 release notes, operating guidance,
  compatibility and migration notes, validation details, known limitations, and
  the complete detailed history from Version 0.1 through Version 4.4.
- Preview.png
  A 1920 x 1080 preview generated from this exact Version 4.4 application build.
- .nojekyll
  An empty marker file that tells GitHub Pages to publish the repository as a
  plain static site without Jekyll processing.

All BOTD artwork, rink graphics, default rosters, Playbook templates, audio
synthesis, application logic, default data, and interface assets are embedded in
or generated by index.html.

DEPLOYING TO AN EXISTING GITHUB PAGES REPOSITORY

1. Extract BOTD_Hockey_Coaching_Aid_v4.4_GitHub.zip on the computer.
2. Open the root of the repository used by GitHub Pages.
3. Upload index.html, README.txt, Preview.png, and .nojekyll. Do not upload the
   ZIP itself.
4. Replace the repository's existing files with the four Version 4.4 files.
5. Commit the files to the branch configured under Settings > Pages.
6. Wait for the Pages deployment under the repository's Actions tab to finish.
7. Reload the hosted site with Ctrl+F5 on Windows, or perform a full refresh in
   Safari on iPad.

The four files must be placed directly in the repository root. The site entry
file must remain index.html. GitHub Pages does not require a build system for this
application.

RUNNING LOCALLY

Open index.html in a current version of Microsoft Edge, Google Chrome, Mozilla
Firefox, or Safari. A local file address and a GitHub Pages address use separate
browser-storage origins, so saved plays do not move between them automatically.
Export the Playbook JSON from the old address and import it at the new address
when changing locations.

VERSION 4.4 RELEASE NOTES

PLAYER-RELATIVE RH/LH PUCK CARRY

Version 4.4 corrects the puck's attached position so handedness is interpreted
from the player's perspective and relative to the goal that player's team is
attacking.

In Whole Ice:

- A DAWGS RH player carries on the bottom-right side while attacking right.
- A DAWGS LH player carries on the top-right side while attacking right.
- A FLAMINGOS RH player carries on the top-left side while attacking left.
- A FLAMINGOS LH player carries on the bottom-left side while attacking left.

The same attack-vector calculation is used internally in portrait Half Ice. The
puck remains on the correct side of the token after the rink is rotated for
portrait presentation. The corrected offset is used both for displayed
possession and for Pass or Shot source and receiver geometry.

START-OF-TURN PUCK RIGHTS

Version 4.4 distinguishes a player who starts a turn with possession from a
player who collects or steals the puck during that turn.

A player who STARTS the turn with the puck may:

- Move.
- Pass.
- Shoot.
- Drop possession.
- Author those choices in any editing order.
- Continue trimming Skating speed, release point, Pass Speed, Shot power, sauce,
  Ignore defense, and preview time until Done Turn is selected.

A player who STARTS the turn without the puck may:

- Move.
- Take possession during that turn.
- Select possession before or after the skating route is recorded.

A player who collects the puck during a turn does not receive Pass or Shoot in
that same turn. The player begins the next turn in possession and may then use the
Puck Lane. This removes contradictory single-turn puck sequences and makes the
start-of-turn state the authoritative source of Puck Lane rights.

POSSESSION PICKUP AFTER MOVEMENT

The possession control remains available before and after a player's skating
route is traced.

- When a non-possessing player is marked to take the puck and has a route, the
  application finds the closest projected point along that route to the puck.
- The corresponding route timestamp becomes the pickup time.
- The puck remains with its prior state until that time and then attaches to the
  collecting player.
- Changing that player's Skating speed recalculates the pickup timestamp.
- A stationary pickup is permitted when the player is already beside the puck.
- A distant stationary pickup cannot be completed until a route toward the puck
  is provided.

FLEXIBLE MOVE, PASS, SHOT, AND DROP AUTHORING

The player who began the turn in possession no longer has to create a skating
route before selecting Pass or Shoot.

- A stationary Pass or Shot is released at time zero from the player's current
  position.
- A skating route can be added after a Pass or Shot has already been selected.
- Once movement exists, the release slider expands across that route.
- Changing the skating duration recalculates puck geometry without changing the
  traced route shape.
- Dropping possession removes a contradictory pending Pass or Shot.
- Restoring start-of-turn possession makes the Puck Lane available again.
- Line Switch remains hidden while the selected player will possess the puck.

PLAYER ACTIONS DRAWER

The Player Actions drawer now presents only controls that are valid for the
selected player's start-of-turn state.

- The possession toggle remains visible after movement.
- The drawer clearly states whether the player starts with the puck, starts
  without it, collects it during the turn, or drops it.
- A player who starts without the puck sees movement and pickup guidance, while
  Pass and Shoot remain hidden.
- A player who starts with the puck sees Pass and Shoot immediately, whether or
  not a skating route exists.
- Skating controls and Puck Lane controls stay stacked in one timing workspace
  when both are present.

PASS SPEED TERMINOLOGY

The former Puck Speed label is now Pass Speed throughout the active interface,
Pass dialog, timing workspace, toast messages, and timeline descriptions.

Pass Speed remains adjustable from 1 through 10. It changes puck travel speed
without changing either player's skating route. Flat and saucer behavior,
receiver leading, short-second-leg bank eligibility, Ignore defense, and puck
spin remain active.

BLINKING GLOW DEFAULT

Glow now blinks by default whenever it is first enabled.

- With no team in possession, Glow uses the player's primary color.
- A white primary color falls back to cyan for visibility.
- A player whose team possesses the puck defaults to blinking green.
- A player whose opponent possesses the puck defaults to blinking red.
- Color, brightness, blink state, and blink rate can still be changed with the
  Glow gear controls.
- The selected Glow state continues from turn to turn until explicitly cleared.

EXPANDED BOTD PLAYBOOK

Version 4.4 replaces the prior four-template set with ten default entries.

QUICK SETUPS

1. Quick Setup — 5v5 Center Faceoff
   Five skaters and one goalie per side, with the puck loose on the center dot.

2. Quick Setup — 3v3 Center Faceoff
   Three skaters and one goalie per side in center-faceoff spacing.

3. Quick Setup — 5v4 Power Play
   DAWGS use a conventional offensive-zone 1-3-1 presentation against a
   four-player FLAMINGOS penalty-kill box. Both goalies are included.

4. Quick Setup — 3v2 Rush
   Three onside attackers against two defenders, with both goalies included.

5. Quick Setup — 2v1 Rush
   Two onside attackers against one defender, with both goalies included.

CORE PLAYS

1. Core Play — Strong-Side Breakout
   Retrieval, low center support, a strong-side outlet, and a three-lane exit.

2. Core Play — D-to-D Neutral-Zone Regroup
   Defensive reversal, a low center swing, width, and a controlled re-entry.

3. Core Play — 1-2-2 Forecheck
   F1 pressure, F2/F3 support, and two defensemen holding the structure.

4. Half Ice — Low-to-High Overload Cycle
   Wall possession, low interchange, low-to-high puck movement, and a point
   shot with net-front traffic.

5. Half Ice — Box + 1 Defensive-Zone Coverage
   A compact four-player box with one pressure player rotating toward the puck.

The five core plays are widely established coaching-board concepts selected to
cover breakout, regroup, forecheck, offensive-zone possession, and defensive-
zone coverage. Live web browsing was unavailable in the build environment, so
this release does not claim that the selection resulted from a current cross-site
survey of coaching-board websites.

The center-faceoff setups use conventional USA Hockey-compatible spacing. Rush,
power-play, forecheck, and zone-coverage templates are tactical teaching
arrangements, not formations mandated by a playing rule. This application is a
coaching visualization tool and is not an officiating reference.

BLANK NEW BOARDS

Fresh launches without migrated session data and the New command continue to

formation is preferred.

VERSION 4.4 WORKFLOW

1. Open TEAMS to edit team identities and colors.
2. Open ROSTER to edit player information, lines, RH/LH, roles, and leadership.
3. Open SETTINGS to select Whole Ice or Half Ice, token display options, center
   artwork, and offside-indicator visibility.
4. Place players from the benches, or load one of the ten BOTD Playbook entries.
5. Select a rink token directly to open Player Actions.
6. Read the start-of-turn possession status in the drawer.
7. For a starting puck carrier, choose Move, Pass, Shoot, or drop possession in
   whichever editing order is most convenient.
8. For a player who starts without the puck, trace movement and turn on
   possession before or after the route to schedule a collection or steal.
9. Fine-tune every available Skating and Puck Lane slider before Done Turn.
10. Set Glow at any point during the draft turn when visual emphasis is useful.
11. Select the toolbar check mark to finish the turn.
12. Use Undo Last Action, Undo Last Turn, or Cancel to correct authoring.
13. Press Play or scrub the playback control in either direction.
14. Draw or erase telestration marks while playback is running or paused.
15. Save the play to BOTD Playbook and export JSON for backup or transfer.

STORAGE AND MIGRATION

Version 4.4 uses these browser-storage keys:

- botdHockeyCoachingAid.session.v4_4
- botdHockeyCoachingAid.playbook.v4_4

When Version 4.4 is deployed at the same website origin as Version 4.3:

- The existing Version 4.3 session is used when no Version 4.4 session exists.
- User-created Playbook entries are retained.
- Version 4.3 default samples are replaced by the ten Version 4.4 defaults.
- User plays are not overwritten simply because they share a title with a
  default play; only entries explicitly marked as defaults or using reserved
  BOTD default identifiers are regenerated.

A domain, protocol, port, repository path, local-file path, or browser change may
create a different storage origin. Export Playbook JSON before moving and import
it after opening the new address.

KNOWN LIMITATIONS

- A turn supports one puck event. A pickup followed by a Pass or Shot should be
  represented as two turns.
- A possession drop is applied at the start of its turn. Timed drop placement is
  not yet a separate slider-controlled event.
- Moving-obstacle collision prediction is an instructional approximation rather
  than a continuous rigid-body simulation.
- Rounded-board, net, bank-pass, and offside behavior are tactical visualizations,
  not certified officiating or engineering calculations.
- Browser audio and vibration depend on device support, user interaction, mute
  state, and operating-system restrictions.
- Apple Pencil secondary-tap exposure is controlled by iPadOS and Safari and is
  not guaranteed on every hardware and browser combination.
- Browser storage is device- and origin-specific and is not a shared team cloud
  database. Exported JSON remains the portable backup format.
