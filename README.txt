BOTD HOCKEY COACHING AID — VERSION 4.2
Creator: Nicholas Heller
Release date: 2026-08-03

OVERVIEW

BOTD Hockey Coaching Aid is a standalone, browser-based HTML5 coaching board for
building, drawing, animating, saving, and presenting hockey plays. It is designed
for desktop browsers with a mouse and for iPad use with touch or Apple Pencil.
The application is entirely contained in index.html and requires no account,
installation, external JavaScript library, server-side application, or runtime
asset folder.

Nicholas Heller is acknowledged in the HTML source and this README as the creator
of the application, its product concept, coaching workflow, feature direction,
and user experience.

GITHUB PACKAGE CONTENTS

BOTD_Hockey_Coaching_Aid_v4.2_GitHub.zip contains exactly these four current
files at its root. There is no enclosing folder.

- index.html
  The complete Version 4.2 application and GitHub Pages entry point.
- README.txt
  Deployment instructions, Version 4.2 release notes, operating guidance,
  compatibility and migration notes, verification details, and the complete
  detailed history from Version 0.1 through Version 4.2.
- Preview.png
  A 1920 x 1080 preview generated from this exact Version 4.2 application build.
- .nojekyll
  An empty marker file that tells GitHub Pages to publish the repository as a
  plain static site without Jekyll processing.

All BOTD artwork, rink graphics, sample rosters, sample plays, audio synthesis,
application logic, default data, and user-interface assets are embedded in or
generated by index.html.

DEPLOYING TO AN EXISTING GITHUB PAGES REPOSITORY

1. Extract BOTD_Hockey_Coaching_Aid_v4.2_GitHub.zip on the computer.
2. Open the root of the repository used by GitHub Pages.
3. Upload index.html, README.txt, Preview.png, and .nojekyll. Do not upload the
   ZIP itself.
4. Replace the repository's existing files with the four Version 4.2 files.
5. Commit the files to the branch configured under Settings > Pages.
6. Wait for the Pages deployment under the repository's Actions tab to finish.
7. Reload the hosted site with Ctrl+F5 on Windows, or perform a full refresh in
   Safari on iPad.

The files must be placed directly in the repository root. The site entry file
must remain index.html. GitHub Pages does not require a build system for this
application.

RUNNING LOCALLY

Open index.html in a current version of Microsoft Edge, Google Chrome, Mozilla
Firefox, or Safari. A local file address and a GitHub Pages address use separate
browser-storage origins, so saved plays do not move between them automatically.
Export the Playbook JSON from the old address and import it at the new address
when changing locations.

VERSION 4.2 RELEASE NOTES

STRUCTURED LINES AND A READY-TO-COACH STARTING SETUP

Fresh Version 4.2 boards now open as a complete 5-on-5 center-ice faceoff rather
than an empty setup.

- Each team starts with four complete forward lines: LW, C, and RW on Lines 1–4.
- Each team starts with three complete defense pairs: LD and RD on Pairs 1–3.
- Each team also includes two goalies, one coach, and one manager.
- The first forward line, first defense pair, and starting goalie from each team
  are placed on the ice automatically, for 12 on-ice objects total.
- The puck begins loose at center ice.
- DAWGS retain the exact green/black colors #00FC05 and #000000.
- FLAMINGOS retain the exact pink/yellow colors #F100F3 and #FEFE00.
- Existing Version 4.1 data is normalized rather than replaced when migration is
  available.

LINE ASSIGNMENTS, HANDEDNESS, AND A CLEANER ROSTER WORKFLOW

Roster cards now include explicit line and handedness information.

- Skaters can be assigned to Forward Line 1–4 or Defense Pair 1–3 according to
  their listed position.
- Goalies can be assigned as Goalie 1 or Goalie 2.
- RH and LH controls define which side of the token carries the puck.
- RH places the attached puck on the player's right side; LH places it on the
  player's left side.
- Line and handedness values are retained in sessions, saved plays, Playbook
  entries, copied turns, and JSON import/export.
- Coaches and managers have no line assignment or handed puck-carry control.

BENCH ORDER AND LINE-SWITCH PRIORITY

Bench members are now organized in practical line order:

  Forward Line 1, Defense Pair 1,
  Forward Line 2, Defense Pair 2,
  Forward Line 3, Defense Pair 3,
  Forward Line 4, goalies, coach, manager.

Line Switch uses a position-aware rotation. For example, an LW on Line 2 sees
LW Line 3, LW Line 4, and LW Line 1 first. Remaining position groups then appear
in the documented rotation order, with goalies last. Coaches, managers, and
officials are excluded from Line Switch candidates and do not receive a Line
Switch control.

SEND TO BENCH AS A TURN ACTION

A selected on-ice skater or goalie can now choose Send to bench as that turn's
skating-lane action.

- The action is stored in the turn and reproduced during playback.
- A puck carried by that player is released at the exit location.
- Send to bench participates in Undo Last Action, Undo Last Turn, turn copying,
  turn reuse, saved plays, and JSON export/import.

SKATING-LANE PROGRESSION AND STACKED TIMING CONTROLS

The Player Actions drawer now follows the intended authoring sequence more
closely.

1. Establish possession when needed.
2. Trace the skating path.
3. Adjust skating speed.
4. Add Pass or Shoot when the player has possession.
5. Adjust puck release and preview timing.

After a route is traced, the Skating Lane action controls disappear and are
replaced by the skating-speed editor. When the same player also Passes or Shoots,
the skating-speed editor and puck-release/turn-preview controls are stacked in
one timing area so the two events can be synchronized without moving between
separate parts of the drawer.

COMPACT, CONTEXTUAL GLOW

Glow is now a single checkbox with an adjacent gear button.

- Checking Glow immediately adds a turn-scoped highlight.
- Unchecking Glow removes it.
- The gear opens the advanced color, brightness, blinking, and blink-rate
  settings only when customization is needed.
- With no possession, the default glow uses the player's primary color.
- A white primary color automatically falls back to cyan so the highlight stays
  visible on the ice.
- When the player's team possesses the puck, the default is blinking green.
- When the opposing team possesses the puck, the default is blinking red.
- Glow remains a turn action and is retained in copied/reused turns, saved plays,
  Playbooks, and JSON data.

TAG-UP-AWARE OFFSIDE STATUS

The offside light has moved just outside the upper-right rink edge so it no
longer covers the playing surface. SETTINGS now includes Show offside status
light to turn the indicator on or off.

The status sequence is now stateful across a developing play:

- Green: onside.
- Orange: an attacking player entered the offensive zone before the puck, but
  the puck has not yet entered.
- Blinking red: the puck entered while one or more attackers remained in the
  zone without tagging up.
- Green again: every affected attacker tagged up by returning across the blue
  line; a later legal re-entry after the puck remains onside.

The tracker follows forward playback and reconstructs its state when the user
scrubs backward or jumps to another time. Staff objects are excluded. Whole ice
assumes Team A attacks right and Team B attacks left; portrait half ice uses its
single offensive blue line.

LEADERSHIP RULES

- Coaches and managers cannot be Captains or Alternates. Their C and A controls
  are disabled and any incompatible imported leadership values are normalized
  off.
- A team may have no more than two Alternates.
- The old permanent “MAX 2 A” warning text has been removed.
- Attempting to select a third Alternate opens a clear information window and
  leaves the third selection off.
- Goalie leadership remains visually muted but selectable, with the existing
  “tendy” confirmation dialog.

TIMED WHISTLE ACTION AND STAFF ANIMATION

Whistle now behaves like a timed puck-lane event rather than an immediate sound.

- A coach, manager, or official may move or remain stationary.
- The Whistle timing slider places the cue anywhere in that object's route or
  within a stationary turn.
- An inline timing control remains available after the Whistle action is added.
- At the selected moment, the square staff token shakes side to side and swaps
  black and white rapidly for approximately five flashes.
- A short browser-local whistle sound is synthesized when Web Audio and device
  sound policy permit it.
- The turn duration extends far enough to include a late stationary whistle.

TURN ACTION ORDER

Version 4.2 preserves a deterministic action order inside each turn:

1. Possession state changes.
2. Movement and movement-speed timing.
3. Line Switch or Send to bench.
4. Pass, Shoot, or Whistle and its release time.
5. Turn-scoped Glow.

This order is maintained when actions are edited, completed, copied, reused,
saved, exported, imported, and reconstructed during playback.

BASIC VERSION 4.2 WORKFLOW

1. Open TEAMS to edit team names and colors.
2. Open ROSTER to assign members, positions, roles, lines, RH/LH handedness,
   individual colors, and leadership.
3. Open SETTINGS to choose Whole Ice or Half Ice, token labels, center logo, and
   offside-indicator visibility.
4. A fresh board already contains both first units and starting goalies at a
   center-ice faceoff. Tap bench entries to add other objects without selecting
   them automatically.
5. Select a rink token directly to open Player Actions.
6. Toggle Possession when that player has the puck.
7. Drag the token to trace a route, then fine-tune Skating speed.
8. If the player has possession, choose Pass or Shoot and align the release and
   preview sliders with the skating-speed timing.
9. Use Send to bench or Line Switch when appropriate. Staff can use Whistle.
10. Check Glow for instant emphasis; use its gear only for advanced settings.
11. Finish the turn with the bottom check-mark control. Use Undo Last Action,
    Undo Last Turn, or Cancel for corrections.
12. Press Play or drag the playback slider in either direction.
13. Select Pencil or Erase during playback or pause to add live telestration.
14. Use PLAYBOOK to name, save, copy, import, and export plays and Playbooks.

VERSION 4.2 STORAGE AND MIGRATION

Version 4.2 uses its own browser-storage namespace:

- botdHockeyCoachingAid.session.v4_2
- botdHockeyCoachingAid.playbook.v4_2

When no Version 4.2 data exists, the application checks Version 4.1, Version 4.0,
and earlier supported storage keys. Existing teams, rosters, colors, staff,
leadership, logos, marker settings, plays, turns, routes, timing, possession,
glow actions, and Playbook data are normalized into Version 4.2. Legacy roster
members receive practical line and handedness defaults when those fields did not
exist in the source version.

Browser storage is isolated by origin. A local file, a GitHub Pages URL, a custom
domain, and a renamed repository are separate origins. Export Playbook JSON
before moving the site, changing its URL, or clearing browser data.

PRIVACY AND NETWORK USE

- The application makes no network requests.
- There are no analytics, accounts, trackers, advertisements, or cloud APIs.
- Uploaded logos are resized and processed locally.
- Default BOTD artwork is embedded in the HTML.
- Plays remain in the selected browser unless the user exports them.

COMPATIBILITY

Recommended desktop browsers are current Microsoft Edge, Google Chrome, Mozilla
Firefox, and Safari. The app uses Pointer Events for mouse, touch, and Apple
Pencil input. Browser handling of local-file storage, Web Audio, Fullscreen, and
Apple Pencil secondary gestures can vary by platform and iPadOS/browser version.

VERSION 4.2 TECHNICAL NOTES AND KNOWN LIMITATIONS

- The offside tracker is a tactical coaching aid. It uses token centers and app
  coordinates rather than skate/blade geometry, video review, every delayed-
  offside exception, or a governing body's officiating system.
- Attack direction is fixed to Team A/right and Team B/left on whole ice.
- A single puck event per turn remains the clearest supported authoring model; a
  pass-pass or catch-and-shoot sequence should use consecutive turns.
- Staff Whistle audio depends on browser Web Audio permission and device volume.
  The visual shake and black/white flash still run without sound.
- Native Apple Pencil double-tap exposure remains browser- and iPadOS-dependent;
  the Select, Pencil, and Erase toolbar controls are always available.
- Browser-local storage is not a shared team database. Export Playbook JSON for
  backups and transfers between devices or origins.
- Responsive checks were performed in browser-emulated desktop and iPad viewport
  sizes. Physical-device behavior can still vary with Safari and iPadOS releases.
